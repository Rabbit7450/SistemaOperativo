================================================================================

VERSIÓN ACTUAL:
===============
Mi SO v3.2 - Incluye Modo Usuario (Ring 3) y System Calls

Características Principales:
  ✓ Bootloader: 512 bytes exacto + GDT
  ✓ Protected Mode 32-bit
  ✓ Ring 0 (Kernel) + Ring 3 (User)
  ✓ Descriptor Privilege Level (DPL)
  ✓ INT 0x80 System Calls (6 implementados)
  ✓ Scheduler con Prioridades (0-9)
  ✓ Estados de Procesos: RUNNING, READY, SLEEP, ZOMBIE
  ✓ Timer Interrupt
  ✓ Comando TOP con monitoreo
  ✓ 11 Comandos Shell

REQUISITOS OBLIGATORIOS:
========================
- NASM (assembler)
- GCC 32-bit (gcc -m32)
- GNU LD (ld -m elf_i386)
- GNU Make
- QEMU (para ejecutar)

====================

================================================================================
COMPILACIÓN MANUAL PASO A PASO (Si NO quieres usar make)
================================================================================

1. ENSAMBLADOR:
   $ nasm -f bin boot.asm -o boot.bin
   $ ls -l boot.bin    # Debe ser exactamente 512 bytes

2. COMPILAR KERNEL:
   $ gcc -ffreestanding -m32 -c kernel.c -o kernel.o

3. ENLAZAR:
   $ ld -m elf_i386 -o kernel.bin -T linker.ld --oformat binary kernel.o

4. CREAR IMAGEN:
   $ cat boot.bin kernel.bin > os-image.bin

5. EJECUTAR:
   $ qemu-system-i386 -fda os-image.bin

   $ docker build -t mi_so .

   $ docker run --rm -v $(pwd):/work mi_so make run

SOLUCIÓN DE PROBLEMAS
================================================================================

ERROR: gcc: command not found
  Solución: No estás en WSL. Instala WSL2 o usa Docker

ERROR: nasm: command not found
  $ sudo apt install nasm

ERROR: ld: command not found
  $ sudo apt install binutils

ERROR: gcc -m32 fails
  $ sudo apt install gcc-multilib g++-multilib

ERROR: boot.bin no es 512 bytes
  - Verifica boot.asm tiene: times 510-($-$$) db 0
  - Y termina con: dw 0xaa55
  - Run: hexdump -C boot.bin | tail (debe ver "aa 55")

ERROR: QEMU: "could not load os-image.bin"
  - Verifica os-image.bin > 0 bytes: ls -l os-image.bin
  - Verifica boot.bin es 512 bytes exacto
  - Verifica cat boot.bin kernel.bin > os-image.bin se ejecutó

ERROR: Pantalla negra en QEMU
  - Si VE "Bootloader v3.1: Cargando..." → Kernel loading OK
  - Si NO VE nada → Problema en bootloader (boot.asm)
  - Debug: qemu-system-i386 -fda os-image.bin -d int -D debug.log

ERROR: Kernel panic o crash
  - Verifica kernel_main() en kernel.c
  - Verifica VGA memory initialization
  - Verifica linker.ld tiene . = 0x1000

================================================================================
ARQUITETURA DEL SO v3.2
================================================================================

MEMORIA:
  0x00000000 - 0x7BFF:     IVT (Interrupt Vector Table)
  0x7C00 - 0x7DFF:         Bootloader (512 bytes)
  0x1000 - 0x7FFF:         Kernel (28 KB)
  0x90000:                 Stack
  0xB8000:                 VGA Memory (80x25)
  0x10000+:                User Processes (4 KB c/u)

GDT DESCRIPTORS:
  0x08:  Ring 0 Code (Kernel)
  0x10:  Ring 0 Data (Kernel)
  0x1B:  Ring 3 Code (User) ← NUEVO v3.2
  0x23:  Ring 3 Data (User) ← NUEVO v3.2

INTERRUPTS:
  INT 0x08:  Timer (IRQ0)
  INT 0x80:  System Calls (NUEVO v3.2)

SYSCALLS IMPLEMENTADOS:
  1 = exit(code)
  2 = getpid()
  3 = getmem()
  4 = sleep(seconds)
  5 = setpriority(pid, prio)
  6 = getpriority(pid)

INSTRUCCIONES DE COMPILACIÓN - MI SO v3.0
==========================================

Requisitos:
- NASM (Netwide Assembler) para boot.asm
- GCC 32-bit (gcc -m32) para kernel.c
- GNU LD (ld) para enlazar
- QEMU (opcional, para ejecutar)

OPCIÓN 1: Usando Linux/WSL/MinGW (RECOMENDADO)
================================================

1. Limpiar:
   rm -f *.bin *.o os-image.bin

2. Compilar bootloader:
   nasm -f bin boot.asm -o boot.bin

3. Compilar kernel:
   gcc -ffreestanding -m32 -c kernel.c -o kernel.o
   ld -m elf_i386 -o kernel.bin -T linker.ld --oformat binary kernel.o

4. Crear imagen:
   cat boot.bin kernel.bin > os-image.bin

5. Ejecutar (si tienes QEMU):
   qemu-system-i386 -fda os-image.bin

O con Makefile:
   make
   make run

OPCIÓN 2: Si tienes NASM pero no GCC 32-bit
=============================================

1. Instalar MinGW con soporte 32-bit o
   usar Docker: docker run -it gcc:latest

2. Dentro del contenedor:
   apt-get update && apt-get install -y nasm
   gcc -ffreestanding -m32 -c kernel.c -o kernel.o
   ld -m elf_i386 -o kernel.bin -T linker.ld --oformat binary kernel.o

SOLUCIÓN DE PROBLEMAS
======================

Error: "gcc: command not found"
→ Instalar MinGW o usar WSL
→ En WSL: sudo apt install gcc g++ make nasm

Error: "-m32 not recognized"
→ Instalar libgcc-*-multilib
→ En Ubuntu: sudo apt install gcc-multilib g++-multilib

Error: "ld: cannot find -lc"
→ Normal en modo -ffreestanding
→ No agregues -lc ni -nostartfiles innecesariamente

Error: "kernel doesn't load in QEMU"
→ Verifica que kernel está en 0x1000
→ Verifica que boot.bin es exactamente 512 bytes
